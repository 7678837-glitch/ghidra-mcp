# 行为规格

## 产品边界

服务在一个 Python 进程内启动 JVM、加载 Ghidra 项目并提供 MCP 工具。首版只支持 headless 分析，不提供依赖 GUI `PluginTool` 的实时调试器能力。

## 版本兼容

- 已声明基线为 Ghidra 12.0 及以上。
- 不把“无需重新编译”表述为“所有历史版本均受支持”。
- 每个宣称支持的 Ghidra 版本必须通过真实导入、分析、读取、事务写入和持久化恢复测试。

## 工具暴露

- 默认工具总数不得超过 40。
- 批量输入由同一个任务工具接受数组，不另外暴露同义 `batch` 或 `bulk` 工具。
- 按需工具组必须由配置显式启用。
- 工具说明必须包含：功能；输入输出与副作用；何时使用及不应使用的近邻场景。
- 不实现主观命名/注释 lint、模糊 token 子串重命名或脱离真实探针的伪健康状态。

## 配置

- 优先级固定为环境变量 > `.env` > TOML > 默认值。
- 未知配置键快速失败，错误包含键名和来源。
- 敏感值只从环境变量或未入库的 `.env` 读取，日志不得输出值。

## 数据与安全

- 写操作必须在 Ghidra 事务内执行，失败时回滚并返回上下文错误。
- 持久数据位于进程和容器生命周期之外。
- stdio 用于本地集成；Streamable HTTP 必须支持令牌认证和独立健康检查。
- `/health` 必须返回根 `VERSION`、当前 Git commit 和工具 schema 版本。
