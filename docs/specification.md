# 行为规格

## 产品边界

服务在一个 Python 进程内启动 JVM、加载 Ghidra 项目并提供 MCP 工具。首版只支持 headless 静态分析，不提供依赖 GUI `PluginTool` 的实时调试器能力，也不承诺 Ghidra 11.x 或更早版本。

## 版本兼容

- 安全基线为 Ghidra 12.1.2 及以上；服务在 JVM 启动前读取官方 `application.properties` 并拒绝无法确认或低于基线的版本。兼容含义是无需为每个受支持版本重新编译本项目。
- 每个明确列为“已验证”的版本都必须通过真实导入、分析、读取、反编译、事务写入和持久化恢复测试。
- 版本差异必须在 PyGhidra/Ghidra 公共 API 边界内集中处理，不复制内部实现。

## 工具暴露

- 默认工具总数不得超过 40；当前为 34。
- 不暴露同义 `batch`、`bulk`、占位工具或未实现的工具组配置。
- 需要批量处理时由 MCP 客户端对单一任务工具进行有界的顺序调用；服务在一个 JVM 工作线程上串行执行 Ghidra API。
- 工具说明必须包含：功能；输入输出与副作用；何时使用及不应使用的近邻场景。
- 不实现主观命名/注释 lint、模糊 token 子串重命名或脱离真实探针的伪健康状态。

## 配置

- 优先级固定为环境变量 > `.env` > TOML > 默认值。
- 未知 TOML 节或键快速失败，错误包含键名和来源。
- 敏感值只从环境变量或未入库的 `.env` 读取，配置对象表示和日志不得输出值。
- HTTP 端口只接受 1–65535，transport 只接受 `stdio` 或 `streamable-http`；HTTP 还必须显式配置可路由的公开 HTTP(S) 根 URL，鉴权发现元数据不得从监听地址猜测。

## 数据与安全

- 写操作必须在 Ghidra 事务内执行，失败时回滚并返回上下文错误。
- 输入二进制必须存在；持久项目位于配置的 storage root，容器默认为 `/data/projects`。
- stdio 用于本地集成；Streamable HTTP 必须配置至少 32 个 UTF-8 字节的静态 Bearer token。
- 服务不内建 TLS；非回环网络使用时必须由可信反向代理终止 TLS并限制来源。
- `/health` 只报告进程元数据：根 `VERSION`、构建 Git commit 和工具 schema 版本；它不伪装成某个程序已成功分析。

## 有界操作

- 列表工具使用 offset/limit 分页，默认 limit 为 100。
- `memory_read` 原始读取最多 1 MiB；可选解释视图最多 4096 字节，返回 ASCII 与指定字节序/单元宽度的无符号值。
- `memory_search` 模式最多 4096 字节、结果最多 1000 个、单次最多扫描 64 MiB 已初始化内存。
- `decompile_function` 使用显式超时，默认 30 秒；默认输出 50000 字符，调用方可调但硬上限为 200000 字符。
- 自动分析通过可取消 TaskMonitor 执行，默认 300 秒且配置范围 1–3600 秒；超时必须显式失败并回滚当前事务。

## 完成判据

- 单元/契约测试和 Ruff 全绿。
- 安全最低版本和最新公开受支持版本都要对三类原创 ELF `.so` 完成真实集成测试；两者为同一官方版本时只记一次，不用已知不安全版本凑矩阵数量。
- `linux/amd64` 无缓存镜像以非 root 用户运行，健康、鉴权和跨容器卷持久化通过。
- 工作树和完整 Git 历史的项目名称、隐私、凭据扫描无阻断项。
